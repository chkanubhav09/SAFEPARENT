# SAFEPARENT friction log
Started 10 October 2026. Keep observed issues separate from feature wishes.

- Simulation route: Official rules explicitly exempt simulated Alexa+ web experiences from Amazon runtime hooks. Chosen because no physical device, developer access or paid runtime is available. Not an observed Amazon API error; no Amazon integration was attempted.
- Offline workflow: a hostname parser cannot establish site ownership or safety, and simple text patterns miss obfuscated requests. UI therefore uses uncertainty, not a safe/scam verdict.
- Privacy: retaining cases across sessions stores pasted messages on-device. Added clear disclosure and delete-all control rather than silently retaining sensitive input.
- Do not invent SDK failures or friction points for judging. Append actual development/test observations with date, task, steps, expected/actual behavior, workaround, severity and reproducible details.

10 October, initial browser test: port 8080 did not serve the expected app; test timed out before locating the input. Retried on an isolated local test port. No functionality pass claimed for the failed run.

10 October, isolated-port browser rerun passed: empty input, sample analysis, saved checklist/contact/practice, reload persistence, case switching, hostile HTML as text, actual-host parsing, and delete-all after reload. Zero external requests and zero browser JS errors. Desktop and phone layouts inspected at 1280, 390 and 320 px; no horizontal overflow or clipped controls. Full-page preview images are downscaled for viewing, so included a native-width phone crop for readable inspection.

10 October, second build: tool composition was hidden behind intent dispatch, so added a visible per-case workflow showing evidence/state/contact inputs and the chosen next step. Added common labelled-secret redaction before persistence and per-case deletion. Masking is deliberately labelled incomplete. Four new unit tests passed; full browser suite rerun passed. No external API or runtime used.

10 October, expanded browser suite: verified secret masking in actual localStorage, Enter-key question submission and per-case deletion. An initial test assertion mistakenly searched all serialized storage for the word "redacted", which is also a boolean schema key on other cases. Corrected the assertion to inspect case message contents; rerun passed. No app fault was inferred from that test assertion.

10 October, export/recovery tranche: redacted export uses a deliberately small allowlist rather than trying to remove every possible private value from source text. A native preview dialog discloses the remaining timestamp/cue/checklist information before a local download; no share action. Corrupt storage previously reset silently; it now shows a warning and preserves original bytes until explicit discard. New cases remain temporary during recovery. These changes need expanded browser tests in the next tranche.

10 October, review tranche: added keyboard skip link, explicit current-case pressed state, native dialog focus/escape behavior and local export review. Automated axe WCAG 2 A/AA + WCAG 2.1 AA scan returned zero violations on the exercised case screen. This is not a screen-reader/user audit. Keyboard, dialog, download and damaged-storage browser tests passed. Export dialogs inspected at 320/390/1280; recovery banner inspected at 390.

10 October, richer conversation prototype: no local model runtime was installed, and current development environment has about 2 GiB RAM. No large model or inference service was downloaded or paid for. Extended the deterministic conversational planner instead: multi-intent composition, ambiguous completion asks for a step instead of changing state, safety questions preserve uncertainty, instruction-like questions cannot enable external effects. Honest no-LLM label unchanged. This is a free local richer workflow, not a validated open-ended conversational model.

10 October, final v0.3 rerun: 27 engine tests and both browser suites passed. One unit assertion initially expected the old refusal wording ("move money") and did not match the new explicit effect guard ("cannot enable external actions" / "do not transfer money"); updated expected text, without weakening the external-effect refusal. Browser rerun after conversational changes passed; axe returned zero violations on its exercised screen.

16 October, usability/screen-reader pass (v0.4): axe re-run across six states (initial, case, assistant, dialog, practice, recovery) returned zero violations before and after changes. Manual review found focus dropped to <body> on checklist/contact re-renders, silent section reveals, and a textarea overwrite that destroyed unsent drafts when any unrelated action re-rendered. Fixed with per-control focus restoration, focus moves to revealed content, and render() no longer touching the textarea; the post-inspection secret scrub is kept. One browser assertion initially failed after the textarea change because it expected the old scrub-on-render behavior; the scrub was moved into the inspect handler and the suite passes unmodified. Full details in ACCESSIBILITY_REVIEW.md.

16 October, engagement/design tranche (v0.7): added a progress stepper (aria-current), a calm-down breathing beat before evidence when 2+ panic cues fire (role=status, auto-dismiss, Skip control, suppressed under prefers-reduced-motion), chat-style assistant bubbles, at-a-glance cue icons, an all-three-steps completion note, and "never uploads/calls/pays/reports" honesty chips. Screenshot review caught one defect: asking with an empty question rendered an empty "You asked:" bubble; fixed by hiding the bubble for blank questions. 27 engine tests, browser suite, review suite and the six-state axe scan all re-run clean after the changes.
